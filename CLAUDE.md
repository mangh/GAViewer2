# CLAUDE.md — Geometric Algebra Viewer

## Project Overview

This project implements a ***viewer*** for figures defined using ***geometric algebra (GA) expressions***. You can enter expressions *interactively from the keyboard* or *load them from files*. You can interact with the displayed figures (zoom in/out, rotate, view/turn off/remove their elements, etc.).

The starting point is [the GAViewer application source code](https://geometricalgebra.org/downloads/GAViewer-0.86.tar.gz) available on the [Geometric Algebra For Computer Science](https://geometricalgebra.org/index.html) website, extended with the source code of the following external components:

- [FLTK (Fast Light Tool Kit)](https://github.com/fltk/fltk), a cross-platform C++ GUI toolkit, to give the application a graphical interface,
- (optional) [sample figures](https://geometricalgebra.org/downloads/figures.zip) available on [GAViewer interactive book figures](https://geometricalgebra.org/figures.html) page.


The goal of the project is to:

- modernize/restructure the C++ source code (transition to C++20),
- replace geometric algebra generated by [Gaigen](http://sourceforge.net/projects/g25/) with that provided by [Garamon](https://github.com/mangh/garamon) fork,
- ~~upgrade the Antlr2 parser to a newer version or replace it with another parser~~ — done: the ANTLR 2 generated parser was replaced by a hand-written one (`viewer/src/console/consolelangparser.cpp`).

## Grammar (EBNF summary)

The console language is parsed by the hand-written lexer + recursive descent parser in `viewer/src/console/consolelangparser.cpp` (the full EBNF and the lexical rules are in its header comment). Highlights:

- `exprlist = { expr }` is *flat*: an `OPERATOR` token is a prefix of the following `expr` (`consoleStatement::setOp()`), precedence is resolved later by `consoleExprListStmt`; juxtaposition (`a b`) is the geometric product.
- `OPERATOR` tokens include embedded whitespace (`"+ -"` is one token) — the exact token text matters to `setOp()`.
- `IDENTIFIER` vs `FUNCNAME` is decided when a token is lexed, from the parsing scope (`consoleScope::isFunction`); `function`/`batch` declarations and `variable x;` update it. Functions used before their definition need a declaration (`function f();`).
- A statement ends with `;` (quiet) or `,` (verbose: display the result).
- Syntax errors: reported as `[file:]line L:C: message`, the offending top-level statement is skipped.

## Testing

Headless regression tests (`viewer/test`): the `gaviewer_regress` harness links the same `gaviewer_core` static library as the GUI, runs each book figure (`FIG_x_y();`) with `gui_state == NULL`, resumes at every `suspend;`, and dumps per frame the console output plus every object (multivector coordinates and `mvInt` interpretation). The dump is compared with `viewer/test/golden/FIG_x_y.txt`: numbers within a relative tolerance (1e-6), everything else exactly.

```
ctest --test-dir build -j8 [-R FIG_2_2] [--output-on-failure]   # run
cmake --build build --target regress_update_golden              # regenerate golden files (only after an intended change)
```

- Test scripts `viewer/test/scripts/<name>.g` (tests `script.<name>`, golden `golden/<name>.txt`): each defines a console function `<name>()`. `algebra_functions` calls every built-in per-algebra function and operator in all five models (results printed with `print(x, "1.8e")`), `algebra_objects` creates typical blades/versors of every model as objects. A new script is picked up on the next CMake configure; create its golden file with `regress_update_golden` or `gaviewer_regress -I viewer/test/scripts -g viewer/test/golden/<name>.txt -u "<name>();"`.
- Differential tests `gadiff.<algebra>` (`viewer/test/gadiff`, executable `gadiff <algebra> [-v] [-all]`; e3ga, p3ga, c3ga, c5ga, i2ga): every operation of the `ga` layer on the Garamon algebra vs. the same operation of the Gaigen algebra, on ~40-170 multivectors (special values, basis blades, blades, versors, rotors at scales 1, 1e-6, 1e3; those that are not finite are left out) and all their pairs (c5ga: every 11th pair, i2ga: every 3rd, all with `-all`, which takes minutes in a debug build; ~20000-75000 results, tolerance 1e-9 relative to the magnitude of the result; for bilinear products to the size of the operands, given by a `~<scale>` hint token). A Gaigen class and the Garamon namespace of the same name cannot be in one translation unit: `gaigen_side.cpp` and `garamon_side.cpp` each provide an adapter (a template, one instance per algebra) for the shared `gadiff::run<A>()`. meet/join/delta product are compared for blades of moderate size only (otherwise Gaigen's absolute epsilon makes them rounding noise), the meet only if the join is well conditioned (not noise, not a null blade). Gaigen's `compress(epsilon)` (and so `mvType`) drops every grade above 5, a generator bug the `ga` layer does not reproduce: not compared for such multivectors. To add an algebra: a types struct in `gaigen_side.cpp`, a branch in `main()` of `garamon_side.cpp`, the name in the `foreach` of `viewer/test/CMakeLists.txt`.
- Failing test → actual output in `<build>/viewer/test/actual/FIG_x_y.txt`; diff it against the golden file.
- Console output lines that print a multivector (`name = c*blade + ...`) are compared as maps blade -> coefficient (a missing term is 0, tolerance relative to the largest coefficient): rounding noise near the 1e-14 print threshold may be printed on one side only.
- Golden files are references of the Gaigen behaviour: when a test script changes, regenerate its golden file with a build that still uses the Gaigen algebra concerned (if any), not with the converted one.
- Run one figure by hand: `gaviewer_regress -I <figs-src> "FIG_2_2();"` (dump to stdout).
- Code reachable from console functions or GA-file commands must check `gui_state` for NULL (the harness has no GUI).

## Things to Avoid

Garamon pitfalls (each of these compiles and silently computes something else than the Gaigen code it replaces):

- `Mvec::dual()` and `!x` are `x _| I` in Garamon (Gaigen: `x I^-1`, opposite sign in e3ga): use `ga::dual(x)`.
- `a / b` is `a * b.inv()` with an epsilon threshold: use `ga::igp(a, b)` (Gaigen's exact versor inverse).
- `x.grade(k)` takes a grade number (Gaigen `x.grade(mask)` / `x(mask)` took a bitmask `GRADEk`): use `ga::takeGrade(x, mask)`; Garamon's `grade()` returns the highest grade (Gaigen: -1 if not homogeneous): use `ga::grade(x)`.
- `isGrade(0)` is true for zero: use `ga::hasGrade()` / `ga::gradeUsage()`.
- `Mvec` converts to its scalar part by an explicit cast only (`double(mv)`), and is implicitly constructed from arithmetic types only (since the fork's commit 6ee8c11; before, `fabs(mv)` compiled silently and e.g. a `char *` argument competed with `std::string` overloads).
- `a < b` / `a > b` are the left / right contraction, not comparisons.
- In algebras with a non-Euclidean metric (c3ga, ...), Gaigen used Euclidean-metric products (`gpem`, `lcem`, `scpem`, `projectEM`, `versorInverseEM`: all basis vectors orthonormal) inside the delta product (meet, join), `factor` and `mvType`; the `ga` layer does the same, driven by `algebraTraits<MV>::euclideanMetric`. Use the `ga::` algorithms, not hand-written equivalents with the real metric.
- Every `Mvec` operation allocates (`std::list` of Eigen vectors): keep multivectors out of hot loops and out of code run on every repaint (e.g. `geosphere.cpp` uses plain `std::array<double, 3>`; the tubes, arrow heads and mesh normals use the plain 3D geometry of `tubegeometry.h`, checked against the multivector formulas it replaces by the test `tubegeometry`), and never put an `Mvec` in `malloc`/`realloc`'ed memory.

To check a conversion for the silent cases: temporarily add `static_assert(sizeof(T) == 0, ...)` to `Mvec::dual()`, `operator!` and `operator/(const Mvec&)` in the generated `build/garamon/generated/garamon_<name>/src/<name>/Mvec.hpp` and rebuild: every use is then a compile error (restore the file afterwards).
